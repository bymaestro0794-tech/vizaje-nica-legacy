# Checkout phone validation — legacy rollback reference

Этот файл сохраняет прежнее строгое правило checkout перед переходом на гибкую проверку.

## Старое правило

Номер очищался до цифр и принимался только в двух случаях:

- 8 цифр — локальный молдавский номер;
- 11 цифр, начинающихся с `373` — международная запись Молдовы.

После этого checkout приводил значение к формату `+373XXXXXXXX`.
Номер другой страны, произвольная длина, пустое значение или номер с другим кодом отклонялись.

## Где это было

- `app/js/components/checkout/checkout-recipient.js` — `normalizeMoldovaPhone()`, `isValidMoldovaPhone()`, форматирование и проверка `^373[67]\d{7}$`.
- `app/js/components/checkout/checkout-state.js` — проверка `^373[67]\d{7}$` перед переходом к оплате.
- `app/js/main/05-checkout.js` — старый helper `isValidPhone()` с проверкой 8 цифр или `373 + 8 цифр`.
- `application/controllers/frontend/Cart.php` — серверная нормализация и тот же строгий формат; также был fallback на телефон авторизованного клиента.

## Новое правило

В checkout теперь сохраняются только цифры и необязательный ведущий `+`. Принимается любой код страны и любая длина от 5 цифр. Сервер повторно нормализует значение и отклоняет только пустой номер или значение менее чем с 5 цифрами.

Чтобы вернуться к старому поведению, нужно восстановить блоки, перечисленные выше, одновременно в frontend и backend. Одного изменения JavaScript недостаточно: серверная проверка должна оставаться согласованной с интерфейсом.
