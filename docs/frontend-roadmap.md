# План переноса legacy-магазина в vz-next

Аудит кода выполнен 5 ноября 2026 года. Это проверка маршрутов, контроллеров и
компонентов; `tsc --noEmit` прошёл. Браузерные сценарии и сборка не запускались.
Статус «есть» означает, что код реализации найден, но полное совпадение с legacy
не подтверждено.

## Принципы переноса

- Legacy — источник текущего поведения и бизнес-правил. Перед переносом
  проверяем controller, model, view, JavaScript и связанные таблицы.
- Переносим по одному сквозному сценарию: данные → серверная логика → UI →
  состояния загрузки/ошибки/пустого результата → сравнение с legacy.
- Не переписываем все страницы одним большим проходом и не придумываем новые
  бизнес-правила.
- UI Next делаем на Tailwind. `b2b.css` пока остаётся исключением. Новые
  библиотеки добавляем только при конкретной необходимости: основной стек уже
  установлен — Next.js, TypeScript, Tailwind, Drizzle/MySQL, Zod и Zustand.
- WorkApp/1С и Meilisearch переносим поздно, после стабилизации B2C. Админка —
  последний продуктовый этап.

## Значения статусов

- **Есть в Next** — маршрут или код функции найден; полного соответствия legacy
  это само по себе не доказывает.
- **Частично** — базовый сценарий реализован, но есть неподтверждённые или
  отсутствующие правила, состояния либо интеграции.
- **Нет / отложено** — реализация не обнаружена или сознательно перенесена.

### Серверная основа и библиотеки

В Next найдены серверные функции каталога, товара, главной, акций, подборок,
блога/новостей, магазинов, контактов, доставки, сертификатов, авторизации и
кабинета. Есть API для auth, account, cart, quote, promocode, gift promotions,
orders, contact, cookie consent и blog likes. Данные читаются из MySQL через
Drizzle; заказ сохраняется в локальные таблицы.

Текущий стек: Next.js 16, React 19, TypeScript, Tailwind 4, Drizzle + MySQL,
Zod, Zustand и lucide-react. Новая ORM или UI-платформа для начала миграции не
требуется.

#### Статус языковых URL после этапа 0

- `/` направляет на `/ru`; `/ro` имеет отдельный layout, а `proxy` задаёт
  `lang="ro"` для документа.
- `localizedPath` и переключатель языка переводят известные первые сегменты
  legacy URL, сохраняют query/hash и ведут на поддерживаемый маршрут целевой
  локали. Переходы с отложенных страниц онлайн-сертификата возвращаются на
  главную выбранного языка.
- RU и RO имеют отдельные layout; румынский catch-all и RU compatibility
  catch-all разрешают legacy aliases. В Next добавлен маршрут товара по legacy
  адресу `/ru/katalog/:category/:product`; алиасы `catalog-categories` и
  `catalog-collections` ведут в каталог обеих локалей.
- Header и footer берут язык из текущего маршрута; ссылки меню нормализуют
  prefix и выбирают URI нужной локали. Корзина, checkout, кабинет, блог, новости,
  акции, подборки и страницы товара получают locale; отдельная корзина доступна
  по `/ru/korzina` и `/ro/cos`.
- Добавлены route-aliases для страниц доставки, сертификатов подлинности,
  магазинов, акций, новостей и др. Румынская доставка читает румынскую запись;
  checkout success/error, auth reset-email, уведомления корзины и переходы из
  drawer используют текущий язык. B2B-лендинг оставлен на английском, как в
  legacy.
- Статический проход подтвердил наличие обработчиков маршрутов и локальных
  ссылок. Финальный критерий остаётся pending до ручного открытия прямых URL и
  переключения языка на desktop/mobile; автоматические тесты и сборка в этом
  проходе не запускались.

### 1. Общая оболочка и единый UI

Сверить header/footer, навигацию, cookie consent, search/login/cart drawer,
toast, focus/Escape, блокировку скролла и мобильное поведение. Постепенно
перевести оставшиеся storefront-стили на Tailwind; `b2b.css` не менять.

**Текущий прогресс, 5 ноября 2026:** header, footer, cookie consent, авторизация
и toast используют Tailwind-классы; старые CSS-правила auth/toast удалены из
`globals.css`, `b2b.css` оставлен без изменений. Добавлены фокус внутри активного
drawer, закрытие по Escape и возврат фокуса; body scroll lock сохраняется. Cart и
login drawer открываются через portal, поэтому не скрываются вместе с desktop
частью header на телефонах. Cookie-панель получает фокус при открытии, закрывается
по Escape и возвращает фокус на кнопку-источник. Мобильные profile/cart-кнопки
отражают открытое состояние drawer через `aria-expanded`.

Этап остаётся **частичным** до ручной браузерной сверки. Найденное отличие:
desktop Next пока показывает пять статических пунктов вместо legacy-навигации,
собранной из категорий и меню, с mega-menu. Это сверить и перенести в этом этапе.
Search drawer пока является обычной формой; подсказки, история и популярные
запросы остаются в этапе 3. Проверить прямые переходы RU/RO, закрытие каждого
drawer, возврат фокуса и мобильную ширину.

### 2. Товар и каталоги

Сверить карточку, PDP, каталог, категории, бренды и коллекции: доступность,
изображения, варианты, цена, скидка, сортировка, фильтрация и пагинация.
Функциональность рейтинга/отзывов не включать.

**Готово, когда:** товар и параметры дают ожидаемые выдачу, цену и варианты в
legacy и Next; действует принятое правило не показывать товар без обязательных
цены и изображения.

### 3. Поиск на MySQL

Закрыть обычный поиск, подсказки, историю/популярные запросы и базовые фильтры,
которые можно обслужить текущей БД. Сохранить контракт, позволяющий позднее
заменить движок без переделки UI. **Meilisearch подключить ближе к завершению.**

### 4. Корзина, checkout и заказ

Сверить cart drawer, количества, подарки, скидки, бонусы, доставку, серверную
проверку и создание заказа. Затем дополнить checkout по фактическим правилам
legacy: адрес, самовывоз, магазин, способы оплаты и ошибки. Paynet подключить
после стабилизации базового оформления.

**Готово, когда:** заказ создаётся только после серверной проверки; итог
корзины совпадает с итогом заказа; ошибки и исход операции корректно отражены.

### 5. Авторизация и личный кабинет

Сверить регистрацию, вход, SMS, восстановление пароля, профиль, избранное,

### 6. Маркетинговые сценарии

Закрыть виды акций, gifts, промокодов и бонусных правил. Добавить рулетку

### 7. Остальные B2C-страницы

Сверить главную, магазины, доставку, контакты, legal, блог/новости, загрузку

Онлайн-конструктор сертификатов и нишевая парфюмерия остаются отдельными

### 8. Внешние интеграции и выпуск

готовности соответствующих storefront API и интеграций.

## Как закрываем один раздел

1. Находим legacy URL и связанные controller/model/view/JS/таблицы.
2. Записываем правила и состояния: обычное, пустое, загрузка, ошибка,
   недоступность, авторизованный пользователь и гость.
3. Проверяем, что уже есть в Next, и не дублируем готовое.
4. Реализуем недостающий серверный контракт с TypeScript/Zod и UI на Tailwind.
5. Сверяем поведение с legacy на desktop/mobile и в RU/RO.
6. Запускаем уместную проверку этапа и отмечаем статус в этом документе.

Этап считается **готовым**, когда работает сквозной сценарий, данные и цены
проверяются сервером, обработаны ошибки и пустые состояния, соблюдены URL и язык,
и нет известных расхождений с legacy. Факт открытия страницы критерием готовности
не является.

## Границы аудита

Это статическая инвентаризация исходников. В Next внесены правки языковой
маршрутизации и общих B2C-компонентов; legacy не менялся. Сборка и тесты не
запускались. До этого прохода в рабочем дереве уже были незакоммиченные
изменения в legacy-файлах и кеше; они сохранены и не относятся к этому плану.
